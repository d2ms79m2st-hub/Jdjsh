# مساعد بدر

منصة عربية RTL لاكتشاف متجر **بدر أبا الخيل للعود والعطور والزعفران** والتفاعل مع مساعد متخصص يحمل الشعار الرسمي **«عزنا بطيبنا»**. الواجهة مبنية لتقريب العميل من المصدر الرسمي بدل نسخ كتالوج غير موثق.

## ما يعمل في النسخة الحالية

- صفحة رئيسية فاخرة ومتجاوبة للجوال والكمبيوتر.
- محادثة «مساعد بدر» عبر مسار خادم tRPC. نقطة تكامل Manus LLM جاهزة على الخادم، لكن وضع الحماية يستخدم الردود المؤكدة حاليًا حتى يتم ربط كتالوج رسمي للمنتجات؛ لا يسمح النظام للنموذج بإضافة أوصاف أو أسعار غير موثقة.
- روابط موثقة للموقع الرسمي، قسم **خشب العود**، قسم **العطور**، وصفحة **التخفيضات**.
- صفحة دليل متجر توضح حالة مصدر البيانات ولا تعرض منتجات أو أسعارًا غير مؤكدة.
- صفحة منطقة إدارة محمية بمسار تسجيل الدخول الجاهز، مع توضيح ما يحتاج إلى تفعيل قبل عرض أدوات التعديل.
- بيان مسارات الموقع في `client/public/manus-routes.json` ومسار صحة في `/api/health`.

## التشغيل المحلي

المتطلبات: Node.js متوافق مع المشروع وpnpm 10.18.0.

```bash
pnpm install
pnpm dev
```

يفتح الخادم على المنفذ `3000` افتراضيًا. للتشغيل الثابت فقط:

```bash
pnpm dev:static
```

## الفحوصات والبناء

```bash
pnpm check
pnpm test
pnpm build
pnpm start
```

## قاعدة البيانات

المشروع مهيأ لقاعدة MySQL المُدارة عبر `DATABASE_URL`، وتوجد جداول المستخدمين الأساسية في `drizzle/schema.ts`. عند إضافة جداول المنتجات وقاعدة المعرفة، تُكتب migration مقصودة ثم تُشغّل:

```bash
pnpm db:push
```

بيئة التطوير والنشر تستخدمان قاعدة المشروع نفسها؛ لا تُنفذ عمليات حذف أو seed تدميرية دون نسخة احتياطية وموافقة.

## متغيرات البيئة

- `DATABASE_URL`: يحقنه Webdev عند تفعيل قاعدة البيانات.
- `MANUS_API_URL` و`MANUS_API_KEY`: يحقنهما Webdev لاستخدام خدمة LLM من الخادم، ولا يتم تضمينهما في المتصفح.
- متغيرات OAuth القياسية يوفرها قالب Manus لتسجيل الدخول.

لا ترفع ملفات `.env` أو مفاتيح API أو بيانات العملاء إلى GitHub.

## ما يحتاج إعدادًا إضافيًا

1. ربط كتالوج Salla أو API رسمي للمنتجات والصور والأسعار والمخزون.
2. إضافة جداول قاعدة المعرفة والمحادثات والتوصيات، ثم تفعيل الاسترجاع الدلالي.
3. تحديد صلاحيات الإدارة وإضافة لوحة التعديل وسجل التغييرات.
4. إضافة بوابة الدفع والشحن في بيئة اختبار ثم الإنتاج، دون تخزين بيانات البطاقات.
5. إعداد Telegram أو البريد أو WhatsApp Business أو n8n عبر التكاملات الرسمية فقط.
6. ربط GitHub والنشر بعد تأكيد مالك المستودع من بطاقة الربط الرسمية في Webdev.

## النشر

يستخدم المشروع إعداد Webdev القياسي: `Dockerfile`، و`/api/health`، و`pnpm build`. لا يتم اعتبار النشر أو ربط GitHub مكتملًا إلا بعد ظهور receipt ناجح من Webdev. إعداد CI/CD وGitHub Actions مرتبط بصلاحيات المستودع بعد إتمام الربط.
